# Design Better UI With Real Product Examples

Design, build, redesign, or improve web and mobile interfaces without starting from generic defaults.

![Real App Designs with UIZZE](https://uizze.com/landing/ui-radar-skill-banner.png)

## Start With the Product

Make the UI unmistakably right for this product and its users—not a generic template or borrowed style. Make the main task obvious and effortless. Keep only what helps it; simple means low friction, not emptiness. Create character through one or two coherent product choices in layout, type, color, imagery, or motion—not decoration. Preserve competent work, the local system, and platform conventions unless the task requires change. Use UIZZE evidence or materials only for a real decision; adapt rather than copy, and ignore weak evidence. Build only the requested scope and necessary states, render it, fix observable breakage, and never add UI to prove novelty or UIZZE.

This skill is standalone. It does not require MCP, authentication, payment, or another skill.

## Design With Judgment

Organize the interface around the real task and product objects. Reuse the local system when it works. A familiar pattern is fine when it is the easiest option for the user; difference for its own sake is not product specificity.

Give visible controls real outcomes, preserve media proportions, and make responsive behavior fit the actual content. Do not add UI merely to prove UIZZE was used.

## Check the Actual Result

Render the relevant view and exercise the critical interaction in scope. Fix clipping, overlap, inert controls, distorted media, inaccessible names or focus, unreadable contrast, privacy leaks, overflow, or hierarchy that blocks the main task. Do not turn stylistic preference or lack of novelty into a defect.
